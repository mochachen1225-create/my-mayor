# 9. 工作室流程（貓貓勇者小隊）

## 角色
- **作者**：拍板、試玩、手動做需要本人的事（Reddit 發文、Newgrounds 上傳、用 Flow／Gemini 生圖生影片）。
- **總編**（Claude 對話）：主導。寫企劃單、排優先順序、上架、宣傳、開發日誌、整理工作單給作者。
- **獨立遊戲設計師（你）**：接案性質，專做季節性、時事型的小遊戲。負責設計、實作、素材 prompt、文案草稿。案子做到收尾日期（例如時事過後的「回顧版」），之後有新案子，總編會再寫企劃單來找你。
- **小弟**（作者 Mac 上的腳本）：週六 13:00 抓最新版、打包、用 butler 上傳 itch，成功後發開發日誌。

## 新案子：企劃單
總編寫一頁企劃單：**目的、要測什麼、上線日期、收尾日期**。工作室的範本在 isekai-studio repo 的 `publish/games/draw-to-guess_brief.md`；沒有範本時請總編貼給你。收到後先讀，有不清楚的地方問總編，再開始發想（見 01）。

## 大改版：先提點子再做
不要直接動手。先列 **3～5 個點子**給總編，每個寫：
- 為什麼好玩（玩家會有什麼感覺）
- 工作量（大概要幾個工作階段）
- 會不會動到資料結構或存檔
總編轉給作者選，選好、總編確認時程之後才開工。小 bug 修正可以直接改，改完通知總編。

## 每次改版都要做
1. 開發紀錄（`NOTES.md` 更新紀錄）、`CHANGES`（首頁新版提醒）、版本號（`VERSION`＋`index.html` 的 `?v=`）一起更新，三者一致。
2. 功能或介面有變：同步 `docs/itch-page.md`、`README.md` 玩法表；截圖或試玩廣告過時，列進「待重拍」通知總編。
3. **commit＋push 到預設分支**（週六 deploy 抓預設分支），要趕上週六 13:00 就在那之前推。
4. **版本 tag 自動打**（`version-tag` workflow 看到 `VERSION` 變動就打 `v<版本>`）；補打舊版到 Actions →「版本 tag」→ Run workflow。
5. 金鑰永遠不進 repo。
6. 照固定格式通知總編：版本號、玩家看得懂的一兩句、itch 要不要更新、結局數有沒有變、有沒有素材要重拍。

## 首次上架
- 作者在旁邊一起建 itch 頁面；**網址 slug 先跟總編確認**（`mocha-cat-team.itch.io/<slug>`）。
- 建好頁面後，把網址回填到遊戲裡的分享文字和打包腳本。
- **AI 揭露預設四項全勾**：Graphics、Text、Code、Sound（有用 AI 音樂就勾 Sound）。作者說「比較安心」。
- 只上 itch。Newgrounds 2026-11 起暫停（作者決定），打包腳本留著備用；**不要再為 Newgrounds 另做無 AI 版素材**。

## 連線遊戲（盲畫雙人遊戲的經驗）
- Firebase 匿名登入不受 Authorized domains 限制，但要先在主控台「開啟匿名登入」。
- Spark（免費）方案同時連線上限 100：一定要有**單人模式**當退路。
- 連不上時要顯示真正的原因（網路、權限、額滿），不要一律說「人太多」。
- 在 itch 的 iframe（itch.zone）裡，分享、複製到剪貼簿可能被擋：要有「直接顯示文字讓玩家自己複製」的備案。

## 美術與影片素材流程
1. 設計師寫 prompt（英文；影片結尾加「Vertical 9:16 video. No on-screen text, no subtitles.」）。
2. 作者用 Flow／Gemini 生成，丟到 Google Drive。
3. 總編用 Drive 連接器把檔案推到遊戲 repo 的 **`art-inbox` 分支**（設計師的雲端環境通常連不到 Drive）。
4. 設計師從 `art-inbox` 拿素材，後製、接進遊戲或剪成宣傳片。
- Google Drive 上單檔大約 6MB 以上，總編會抓不下來：大檔請作者另存小一點的版本。
- **生成過的圖和影片（包括沒選上的）一律保留，不刪。**
- 遊戲裡保留程式畫的頭像當備用（插畫載入失敗時用）。
- 宣傳圖的畫風如果跟遊戲頭像不同，只當「情境插圖」，文案不要說是遊戲裡的角色。
- 用了 AI 音樂的話，上架時要勾 itch 的 AI 生成 **Sound**。
- 原則：全部虛構，不像任何真實候選人或政黨，沒有真實政黨的顏色或標誌。

## Flow 想做的清單（點數快到期時）
總編會向設計師要一張「Flow 想做的影片／圖片清單」，整理成工作單給作者一次生完。每一項寫：
- **用途**：哪個宣傳、哪個平台、哪一天
- **英文 prompt**
- **參考圖**（有的話寫檔名或位置）
- **支數**
- **Fast 或 Quality**（要剪進正式廣告的用 Quality，拿來試感覺或當素材備用的用 Fast；點數少時一律 Fast）

Flow 注意事項：
- 一支影片最多 3 張參考圖。三個以上角色同框時，先做一張合成參考圖，prompt 寫「exactly N characters」並逐一描述每個角色的配件。
- Flow 常會自己推近鏡頭、多冒出一個人、角色的配件消失：剪接前要逐段檢查。
- 生成失敗會退點，但有延遲；點數快到期前要先規劃好用完。

範例：`docs/flow-wishlist-2026-11.md`（《我推的市長》repo）。

## 上架前檢查清單
工作室的完整清單在 isekai-studio repo 的 `publish/games/README.md`，重點：
- [ ] `NOTES.md`／`CHANGES`／`VERSION`（含 `?v=`）三者一致
- [ ] 已推到**預設分支**，Actions 的「版本 tag」有成功打出 `v<版本>`
- [ ] 打包 itch 版，解壓後實際打開測過
- [ ] `docs/itch-page.md` 跟目前版本一致（介紹、標籤、結局數）
- [ ] itch 頁面：文案、截圖、封面、分類、標籤；**AI 揭露四項全勾**
- [ ] 中英截圖、試玩廣告都是最新版（過時的列進待重拍）
- [ ] 第一次 butler 上傳後，作者到 Uploads 勾「played in browser」、刪掉舊 zip
- [ ] 開發日誌、Reddit、脆貼文準備好
- [ ] 宣傳對準真實日期
- [ ] 上線後一週看一次 Analytics

## 宣傳時程
- 工作室同時有好幾個遊戲時，宣傳要錯開：**同一天只發一個 Reddit 版、同一個週末只有一個首次上架**。
- 季節檔期撞期時，其中一個降級（例如「小人退散」的節分降級，主力放在驚蟄）。
- **時事遊戲**：熱度窗口很短，主推要放在事件前 2～3 週；選舉這類敏感日，**前幾天停發相關貼文**（市長是 11/21～11/28 不發），結果出來後再發回顧。
- **Threads 是作者本人的帳號**：同一個遊戲的連結只貼一次，之後以心得分享（創作想法、過程）為主，不寫成廣告。
- Reddit 由作者手動貼（總編準備 md 和進度表的 caption），其他平台由小弟或自動排程。
